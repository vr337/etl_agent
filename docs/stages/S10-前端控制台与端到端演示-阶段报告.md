1. **跨 S9 遗留缺陷：CRLF 破坏冻结制品哈希（本阶段前置检查发现并修复）**
   现象：Windows 上 `core.autocrlf=true` 把 `benchmarks/harness-v2/v1/*.json` 检出为 CRLF
   （scenarios.json 233 CRLF / 0 LF），工作区 SHA256 `606c84b5…` ≠ manifest 冻结值 `baa80780…`
   → `load_suite()` 抛 `BenchmarkStateConflict`；后果是**全量回归从 834 掉到 19 failed + 24 errors**，
   且任何 Windows 全新克隆都会失败（不只是本机问题）。
   修复：① 新增仓库根 **`.gitattributes`**，对冻结制品 `benchmarks/** -text`（强制不转换，
   使「仓库字节 == 工作区字节 == 哈希输入」），其余文本统一 LF 落库；② 三个 JSON 强制回 LF。
   验证：`scenarios.json` CRLF=0 / `baa80780…` ✓、`baseline.json` CRLF=0 / `3cf8da49…` ✓；
   回归恢复 **834 passed, 2 skipped**。
   人类明确要求：**此修复必须包含在 S10 提交里，`git_ship` 的 files 列表要加 `.gitattributes`**。

4. **实现期发现的真实缺陷（4 处，均已修复并给出根因）**
   - **`App.vue` 未传默认插槽 → 全站内容空白**：`AppShell` 是「外壳 + 默认插槽」结构，
     只写 `<AppShell />` 会渲染空壳（左导航/顶栏在、主内容区永远空白）。
     **`vue-tsc` / `eslint` / `vite build` 全部通过**——插槽可选，类型系统对「渲染空内容」无感。
     **仅截图能发现**（首轮截图 S1 主内容区空白）。修复：`<AppShell><RouterView /></AppShell>`。
     这是本阶段最有价值的发现，已写入 workspace memory。
   - **块注释内 `*/` 提前闭合注释 → `TS1160 Unterminated template literal`**：
     `/** 口径：字段名与 `src/etl_agent/*/schemas.py` 的 Pydantic 模型对齐 */` 中
     `` */schemas `` 的 `*/` 提前关闭块注释，TS 把 `` `src/etl_agent/*/ `` 当模板字符串起始。
     报错行号指向**文件末行**（极具误导性）。排查手法：**二分注释掉文件前缀**精确定位到第 8 行。
     修复：改写为「各模块 `schemas.py`」，并在全前端范围内扫描确认无同类隐患（0 命中）。
   - **ESLint 9 缺扁平配置 → lint 静默失效**：ESLint 9 起废弃 `.eslintrc.*`，缺 `eslint.config.js`
     时直接报「couldn't find an eslint.config.(js|mjs|cjs) file」并**跳过全部检查**——
     等于 lint 门形同虚设。修复：新增 `eslint.config.js`（`@eslint/js` + `typescript-eslint` +
     `eslint-plugin-vue` 扁平配置），并把 `scripts/**` 纳入 Node 全局。
