【执行偏差与口径说明（均已按更严谨一侧实现，逐条给出证据）】

1. **场景与真实 PDP 契约不符（实现期发现的真实缺陷，3 条场景改写）**
   中断点前 S9-L0-003/005/009 三条场景按**想象中的规则**编写，跑 L0 层时无法命中预期规则：
   - S9-L0-003 用 `side_effect_type: ROLLBACK_DORIS` 表达「破坏性命令」——但真实
     `harness/pdp/rules` 破坏性判定读的是 `command_type`，且破坏性注册表
     `harness/side_effects/registry.py` 的键是 `ROLLBACK_DORIS`（`tool_name=doris.rollback`）；
   - S9-L0-005 断言「无白名单连接器 → DENY」——真实 PDP **没有**连接器白名单规则，
     空 classifications 会落到 ROUTINE → ALLOW；
   - S9-L0-009 断言「预算超限」——未给出预算维度，无法触发 `HARNESS-P1-BUDGET-EXCEED`。
   处置：三场景改写为**真实可选中的路径**——S9-L0-003 改 `command_type: ROLLBACK_DORIS`
   + `tool_name: doris.rollback`；S9-L0-005 改为 **HOCON 明文凭据注入**
   （`password = "injected-plaintext"`，命中 `HARNESS-P0-PLAINTEXT-CREDENTIAL`）；
   S9-L0-009 改为 **字节数维度预算超限**（`budget: {max_bytes: 107374182400}`，
   命中 `HARNESS-P1-BUDGET-EXCEED`）。改写后 `scenarios.json` SHA256 变化，
   同步更新 `manifest.json` 的两个 sha256（见偏差说明 2）。

2. **manifest 冻结校验按预期拒绝（口径：冻结校验生效，人工确认后更新）**
   改写 scenarios.json 后 `load_suite` 抛 `BenchmarkStateConflict`（scenarios.json SHA256
   与 manifest 不符）——**这正是冻结机制的预期行为**（S9 禁止事项 15：禁止篡改 manifest）。
   处置：人工确认改写内容合法后，更新 manifest 两个 sha256：
   - scenarios.json SHA256 → `baa807804bb5989485a9bac880497d7e760d7164d0f74efc131d360f07957e8b`
   - manifest_sha256 → `cd68d5a07a6b09862a8431d219787953aaa2f093f52eadfb14a6dfa1531660af`
   （baseline.json 未动，SHA256 保持 `3cf8da49...`）

3. **`report_sha256` 不可复现（实现期发现的真实缺陷）**
   `benchmark/service.py::_report_digest` 把全部 metrics 纳入摘要，其中
   `non_llm_p95_regression` 是**墙钟派生量**（L2 层实测毫秒 → 与基准比），
   两次同套件运行的 P95 微抖动会让 `report_sha256` 每次都不同 →
   违反 AC-09 的 `reproducibility_rate = 1.0` 门禁（当时该门禁靠「同输入同输出」自证，
   反被自身缺陷证伪）。
   处置：新增 `_DIGEST_EXCLUDED_METRICS = frozenset({"non_llm_p95_regression"})`
   与 `_quantize_p95(value_ms) -> round(value_ms, 2)`；摘要只取**确定性事实**，
   并把 P95 量化到 2 位小数后再入 metrics。`test_report_digest_reproducible` 由红转绿。

4. **safety 路由 MissingGreenlet（实现期发现的真实缺陷，7 处调用点）**
   `safety/router.py` 的 `_proposal_view` / `_release_view` 在 `session.flush()` 后读
   `TimestampMixin.updated_at`（`server_default=func.now(), onupdate=func.now()`，
   flush 后处于过期态）→ 异步下直读触发 `MissingGreenlet`（S8 的 `rollback/router.py`
   已踩过同一坑）。
   处置：新增 `_proposal_view_async(session, row)` / `_release_view_async(session, row)`，
   先 `await session.refresh(row)` 固化过期列再组装视图；8 处调用点全部改为 await 异步版本
   （第 147/164/183/215/243/269/296/321/363 行）。

5. **CLI 污染开发库（恢复期发现的真实缺陷，回归阻断）**
   全量回归出现 3 例失败：`tests/projects/test_bootstrap.py::test_bootstrap_valid /
   _invalid_token / _idempotent`（均 `assert 409 == 200`）。根因：修复前的 CLI
   `_run` 用 `async with engine.begin()` **提交**了 `benchmark-cli` 项目 + 1 条
   `BenchmarkRun`（`benchmark_runs.project_id` 非空，CLI 需一个归属项目行），
   破坏了 bootstrap 用例的「空库」前置（`count(Project) == 0`）。
   处置（S9 禁止事项：CI 门禁不得污染环境）：
   - `cli.py::_run` 改为 `engine.connect()` + **无条件 `transaction.rollback()`**，
     session 用 `join_transaction_mode="create_savepoint"`；
   - 抽出 `_ephemeral_project(session)`（库里无项目时造一行临时项目，随事务一起消失）；
   - 清理开发库残留 1 项目 + 1 运行记录（已核对 projects/benchmark_runs 归零）；
   - 新增回归用例 `test_run_leaves_no_residue_in_database`：跑完 `_run` 前后比对
     `Project` / `BenchmarkRun` 计数必须相等（用 `db_session` 夹具绑定 CLI 的 engine，
     避免夹具 teardown 后再碰全局 engine 触发 `Event loop is closed`）。
