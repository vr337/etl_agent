【执行偏差与口径说明（均已按更严谨一侧实现，逐条给出证据）】

1. **回滚域的项目归属经 `Pipeline` 中转（实现期发现的真实缺陷）**
   `RollbackRequest` / `ExecutionRun` 均**无** `project_id` 列；项目归属链为
   `ExecutionRun → PipelineVersion.pipeline_id → Pipeline.project_id`。
   中断点前 `rollback/cleanup.py::scan_expired_rollbacks` 与 `rollback/service.py::_project_of_version`
   误写为 `PipelineVersion.project_id`（该列不存在）→ 运行期 AttributeError。
   处置：两处改为 join `Pipeline` 取 `project_id`；`test_cleanup_scan_project_boundary`
   与 `test_rollback_*_cross_project_denied` 断言跨项目边界。

2. **副作用准备单的状态推进需显式刷新（实现期发现的真实缺陷）**
   `rollback/side_effects.py::decide_side_effect` 落审批后**未推进状态**，
   导致「审批已达标却仍停在 WAITING_APPROVAL」→ Commit 期抛 `PreparationStateConflict`。
   处置：新增 `_refresh_status()`（复刻 S6 approve 服务语义）：审批达标 →
   WAITING_APPROVAL→READY，被否 → REJECTED；`_assert_committable` 对 WAITING_APPROVAL
   抛 `ApprovalInsufficient`（与 S6 一致）。`test_side_effect_harness_protocol` 首轮即暴露。

3. **Capability 令牌为 `{json}.{sig}`，非紧凑 JWS（口径对齐）**
   断言曾按 JWS 写 `token.count(".") == 2` 失败。S8 与 S6 的令牌格式一致：
   `{json_body}.{signature}`（单点分隔）。处置：断言改为 `"." in token`；
   `token_sha256 != token`（库中只存摘要，AC-02）。

4. **`ReplayGuard.consume()` 硬编码到 `HarnessCapabilityGrant`（不改 S6，禁止事项 7）**
   S6 的 `ReplayGuard` 无 `model` 参数、硬编码 S6 的授权表；S8 的副作用令牌落在
   `HarnessSideEffectCapabilityGrant`。处置：**不改 S6**，在 side_effects 内新建
   `_consume_grant()` 做条件 UPDATE（`WHERE token_id=... AND token_sha256=... AND consumed_at IS NULL`，
   rowcount≠1 → `CapabilityReplayed`）——与 S6 语义等价但作用于 S8 表。

5. **`SideEffectSpec` 无 `tool_version` 字段（实现期发现的接口不符）**
   中断点前 `side_effect_tool()` 读了 `spec.tool_version`（不存在）→ AttributeError。
   处置：改为入参 `tool_version` 默认 `DEFAULT_TOOL_VERSION = "1.0.0"`。

6. **`resolve_expires_at` 返回绝对时间而非增量（实现期发现的类型错误）**
   中断点前写 `expires_at=moment + _resolve_ttl(ttl)` → `datetime + datetime` TypeError。
   处置：`_resolve_ttl` 改名 `_resolve_expires_at(ttl_seconds, moment)`，直接返回绝对 datetime，
   调用处不再二次相加。

7. **`HarnessCommandOutbox` 无 `token_id` 列（口径）**
   `token_id` 在 `payload` JSON 内而非独立列。测试断言改为 `outbox[0].payload["token_id"]`。

8. **路由视图须异步刷新过期 ORM 属性（实现期发现的 MissingGreenlet）**
   `rollback/router.py::_view` 在 flush/commit 后读 `updated_at`（已过期）→ MissingGreenlet。
   处置：`_view` 改 async，对 `session.dirty` 或未加载 `updated_at` 的行先 `await session.refresh(row)`；
   变更路由在 `session.commit()` **之前**构造视图。

9. **模糊的 `object` 入参收紧为 `Iterable[object]` / `SupervisionRule`（mypy 达标）**
   `supervision/mitigation.py` 的 `strictest_action/risk`、`plan_mitigation` 入参原为 `object`
   （mypy 报 union-attr）；`supervision/rules/__init__.py::ALL_RULES` 原为
   `tuple[SupervisionRule, ...]` 但元素类型未 cast。处置：前者改 `Iterable[object]` 并移除
   `type: ignore`；后者用 `cast("SupervisionRule", ...)` 逐条收敛。

10. **`is_expired` 的空返回处理（mypy 达标）**
    `rollback/retention.py::is_expired` 直接比较可能为 None 的 deadline。
    处置：`deadline = expires_at(...); return deadline is not None and moment > deadline`。

11. **`atomic_swap._connect` 签名收紧（mypy 达标）**
    原 `_connect(self) -> object` 但调用处传 `aiomysql` 参数并访问属性 → 「Too many arguments」/
