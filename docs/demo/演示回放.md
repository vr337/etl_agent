## 1. 本轮修复范围（真实联调暴露的集成缺口）

S10 交付后首轮真实联调（Bootstrap → 控制台）暴露的问题分两类共 4 项：

| # | 缺陷 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | Bootstrap 成功后全部 API **401** `AUTH_401_UNKNOWN_ACTOR` | `X-Actor-ID` 的语义是 **subject**（`actor_resolver` 按 `User.subject` 查表），而 `Bootstrap.vue` 把 `admin_user_id`（UUID 主键）存成了 actor | `Bootstrap.vue` 改存 `adminSubject`（`admin@demo.local`） |
| 2 | Bootstrap 返回 **201 但数据全部丢失**，仍是全站 401 | `projects/router.py` 全部写路由只 flush 未 commit；`get_session` 退出即回滚未提交事务 | 6 个写路由补 `await session.commit()`，并加 commit-spy 回归测试 |
| 3 | Dashboard 右下角等 **405 Method Not Allowed**（≥8 处） | S2~S8 各域只实现「写」端点（POST），前端按 RESTful 惯例请求 `GET /projects/{id}/<resource>` 一律 405 | 补齐 8 个 GET 列表端点（见下表） |
| 4 | `createRelease` 405 | 前端单数 `/release`，后端复数 `/releases`（单数只有 GET） | `safety.ts` 路径改复数 |

补齐的 8 个 GET 列表端点（一律：分页 `limit/offset` + `X-Total-Count` 响应头、列表体裸数组、最小测试；**不改任何既有端点**）：

| 端点 | 前端消费方 | 备注 |
| --- | --- | --- |
| `GET /projects/{id}/executions` | RuntimeCenter | 路由层做字段映射（`trigger_mode←trigger` 等） |
| `GET /projects/{id}/preparations` | 审批台 | 返回 PDP 判决 `decision` |
| `GET /projects/{id}/profiles` | DataSources | 不回列明细与脱敏样本（轻量） |
| `GET /projects/{id}/file-assets` | DataSources | `filename` 为落盘名（后端无原始文件名列，如实不回传） |
| `GET /projects/{id}/agent-runs` | PipelineStudio | `pipeline_id` 经版本链派生 |
| `GET /projects/{id}/connections/{cid}/rotations` | 凭据治理 | 阶段时间轴如实（无逐阶段时间列） |
| `GET /projects/{id}/executions/{rid}/rollbacks` | 运行中心 | `risk_level` 后端无列（PDP 判决在 Harness 准备单），回 `null` |
| `GET /safety-proposals/{pid}/releases` | SafetyGovernance | `{releases:[…]}` 信封（前端既有解包方式） |

另修一处前端噪声：evidence 三个读取端点的「空工作区 404」本是调用方已 catch 的预期分支，
全局错误拦截器仍弹红色通知——为 axios 加 `silent` 容错标记，仅在调用方显式容错时抑制通知
（失败仍 reject，不静默吞错）。

## 2. 复现方法

前置：Docker（`etl_agent_postgres` / `etl_agent_redis`）、后端 :8000、前端 :5173。

```bash
# 0) 前置状态：库内不得有项目（bootstrap 幂等：已有项目 → 409）
docker exec etl_agent_postgres psql -U etl_agent -d etl_agent \
  -c "DELETE FROM project_memberships; DELETE FROM projects; DELETE FROM users;"

# 1) 后端（Windows 兼容入口，SelectorEventLoop）
.venv/Scripts/python.exe scripts/run-api.py          # → :8000

# 2) 前端
cd frontend && npm run dev                            # → :5173

# 3) 真实联调（脚本内完成 Bootstrap，随后逐页采集）
cd frontend
TOKEN=$(grep '^ETL_AGENT_BOOTSTRAP_TOKEN=' ../infra/.env | cut -d= -f2-)
node scripts/capture-e2e.mjs --token "$TOKEN"
```

脚本断言（任一不过即非零退出）：Bootstrap 走真实流程、**无 401、无 405**、
`localStorage.actor_id` 为 subject（而非 UUID）。

### 4 个 404 是预期分支，不是缺陷

| 端点 | 次数 | 语义 |
| --- | --- | --- |
| `GET /projects/{id}/evidence-stream/verify` | 3 | 空工作区未建证据流（后端「不自动建流」，业务 404） |

前端对这两个端点均已显式容错（其中证据读取端点带 `silent` 标记，不再弹红色通知）。
